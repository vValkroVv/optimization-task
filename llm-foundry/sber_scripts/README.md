# Запуск задач с обучением и отладкой

Инструменты для постановки экспериментов и последующего анализа находятся в
[`analytics/`](analytics/README.md).

## Использование `submit_template.py`

Сценарий `submit_template.py` (лучше копируйте для каждой задачи отдельно!) используется для запуска задач как на SLURM, так и на cloud. Настройки задачи и окружения конфигурируются через указание параметров в этом скрипте.

### Настройка параметров

Перед запуском скрипта `submit_template.py`, необходимо настроить следующие параметры:

- **SUBMISSION_TYPE**: Указывает тип системы, на которую будет отправлена задача. Возможные значения — `"slurm"` или `"cloud"`.
- **REGION**: Укажите регион, в который будет отправлена задача. Например, для SLURM это может быть `o3-64`, `o3-128` или `o4`, для cloud — `SR004`, или `SR008`.
- **USER_LOGIN**: Ваш логин. Например, `'fancylogin'`.
- **EXP_NAME**: Название эксперимента. Например, `'MyFancyModel'`.
- **CONFIG_NAME**: Конфигурационный файл эксперимента. Например, `'example.yaml'`.
- **MAX_RETRY**: Максимальное количество попыток перезапуска задачи.
- **N_GPUS и N_WORKERS**: Количество используемых GPU и работников (узлов) соответственно.
- **BASE_IMAGE**: Укажите базовый образ, если не используете значение по умолчанию.
- **SCRIPT_TYPE**: Укажите `"pytorch2"` для запуска PyTorch экспериментов или `"infinity_job"` для inf задачи.
- **SCRIPT_ARGS**: Дополнительные аргументы, передаваемые в скрипт `train.py`.

Также необходимо заполнить обязательные поля `run_name`, `exp_name`, `user` в конфигурационном файле. В качестве примера можно взять конфигурационный файл `sber_configs/default_gigar_config.yaml`.

### Запуск задачи

После настройки всех необходимых параметров в `submit_template.py` (а лучше после копирования), запустите скрипт:

```bash
python submit_template.py
```

Скрипт автоматически подготавливает необходимые окружения и отправляет задачу на выполнение. На экране будут отображены детали отправленной задачи.

После сабмита задачи можно идти на ML Space и смотреть статус своей задачи в разделе `Задачи и окружения`

### Ожидание логов

После отправки задачи рекомендуется подождать некоторое время перед запросом логов, чтобы дать задаче возможность начать выполнение.

## Infinite задача
На кластере выделяется задача с запрашиваемым числом хостов через скрипт, окружение задается докер-образом.

**Процесс отладки:**
1) Сабмит infinite job на кластер, получаем ID задачи
2) В консоли вводим команду `mlspace ssh by-host <ID задачи>-mpimaster-0`. Выполнится подключение к терминалу к ноде ранга 0
3) (Для докера с торчом >2.4 скипаем пункт) Активируется окружение через команду `source /home/user/conda/bin/activate`
4) Запуск пользовтаельского скрипта на многих нодах осуществляетя через скрипт **sber_scripts/infinite_jobs/run.sh**. В этом скрипте необходимо заполнить обязательные поля:
    1) **CODE_PATH** — абсолютный путь до вашего репозитория llm-foundry. `#/home/jovyan/username/llm-foundry`
    2) **YAML_CFG** — имя вашего конфиг файла. Например, `'example.yaml'`.
    3) **NNODES** = N_WORKERS из `submit_template.py`
    4) **NGPUS_PER_NODE** — если меняли количество GPU в ноде

5) Если вам предстоит работать в inf джобе, но при этом не нужно запускать  обучение, зайдите внутри джобы в ваш llm-foundry репозиторий и выполните следующую команду:

    ```bash
    export PYTHONPATH=$(pwd)/:$(pwd)/contrib/composer:$(pwd)/contrib/streaming:$(pwd)/contrib/gigafsdp:$(pwd)/contrib/metric-sampler
    ```

6) **Важно!** После остановки, либо падения задачи рекомендуется запускать скрипт **infinite_jobs/clean.sh**. Он:
    * Убивает зомби процессы, оставшиеся после падения/отсановки вашего скрипта
    * Очищает shared memory, если она не была освобождена в момент падения/отсановки вашего скрипта

| Плюсы  | Минусы  |
|:-------------:|:---------------:|
| До нуля сокращается ожидание запуска скрипта | Шаблон запуска периодически меняется, надо обращаться в cloud и обновлять скрипты **infinite_jobs/run.sh** и **infinite_jobs/clean.sh** |


P.S. Еще можно вот так подключаться к inf задачам на cloud (SR004):

```bash
# master
ssh user@<JOB ID>-mpimaster-0.<JOB ID> -p 2222 -i /home/jovyan/.ssh/ai0001071-01058

# worker 
ssh user@<JOB ID>-mpiworker-0.<JOB ID> -p 2222 -i /home/jovyan/.ssh/ai0001071-01058
```

## Автоматическая передача региона в job_dispatcher_callback_web

### Описание

Теперь регион из `submit_template.py` автоматически передается в конфигурацию `job_dispatcher_callback_web`, что избавляет от необходимости указывать регион несколько раз.

### Использование

#### Вариант 1: Автоматический

В конфигурационном файле просто не указывайте `region` в `job_dispatcher_callback_web`:

```yaml
callbacks:
  job_dispatcher_callback_web:
    # region: # НЕ УКАЗЫВАЕМ! Регион будет взят автоматически из submit_template.py
    username: username
    # ... остальные параметры ...
```

#### Вариант 2: Явное указание (как раньше)

Если вы хотите переопределить регион для конкретного задания, просто укажите его явно:

```yaml
callbacks:
  job_dispatcher_callback_web:
    region: SR008  # Явно указанный регион переопределит автоматический
    username: username
    # ... остальные параметры ...
```

### Пример использования

1. В `submit_template.py` устанавливаете:
   ```python
   REGION = "SR004"  # или любой другой регион
   ```

2. В вашем конфигурационном файле (например, `sft-editable-config.yaml`):
   ```yaml
   callbacks:
     job_dispatcher_callback_web:
       # region: # НЕ УКАЗЫВАЕМ - будет взят SR004 автоматически
       username: username
       # ... остальные параметры ...
   ```

3. При сборке конфигурации в логах увидите:
   ```
   [CONFIG_MERGER] INFO: Automatically set region 'SR004' for job_dispatcher_callback_web
   ```

### Обратная совместимость

Изменения полностью обратно совместимы. Существующие конфигурации с явно указанным регионом продолжат работать как раньше.

### Логирование

- **INFO**: `Automatically set region 'SR004' for job_dispatcher_callback_web`
- **DEBUG**: `Region 'SR008' already set in job_dispatcher_callback_web, automatic setup skipped`

Формат вывода: `[CONFIG_MERGER] LEVEL: message`
