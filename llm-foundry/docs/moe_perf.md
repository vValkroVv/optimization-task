### Алгоритм оценки максимальной пиковой скорости для МоЕ

В данной секции описан алгоритм подбора оптимальной конфигурации обучения MoE с точки зрения перформанса. Важной отличительной особенностью от dense моделей в данном случае является наличие MoE слоёв с неравномерным распределения токенов по экспертам. Учет неравномерного распределения токенов становится критически важен при обучении в ep>1, так как потенциально появляется возможность отправить слишком много токенов на один ep rank и перегрузить девайс по памяти.

Для того чтобы избежать перегрузки девайсов применяется алгоритм дропа токенов, при достяжении заданной емкости ep rank-а лишние токены дропаются. Дроп токенов снижает качество обучения модели и служит только для критических моментов дисбаланса, поэтому важно подбирать конфигурацию таким образом, чтобы минимизировать (в идеале полностью устранить) дропы токенов, но при этом выбрать максимальную по перфу конфигурацию.

+ Для помощи в подборе оптимальной конфигурации предоставлены 3 различных симулятора механизма роутера, которые моделируют различные виды дисбаланса между экспертами:
    - UniformGate - равномерно распределяет токены по всем экспертам (Нужен для оценки перфа);
    - FirstExpertGroupGate - посылает все токены на первые top-k экспертов (Нужен для оценки максимальной ёмкости девайса в токенах);
    - DynamicGate - первые n-шагов используется FirstExpertGroupGate, далее происходит переключение на UniformGate (Нужен для оценки максимальной ёмкости девайса и перфа за один запуск);


0. Базово используем `dispatcher_balancing_strategy="peak_capacity_factor"` и `expert_capacity_factor=2`. Это основной и предпочитаемый способ настройки token drop для сбалансированного MoE роутера, от него и стоит отталкиваться при подборе перформансной конфигурации. Пример:

        ```yaml
        model:
        ...
        config_overrides:
            ...
            dispatcher_balancing_strategy: "peak_capacity_factor"
            expert_capacity_factor: 2
            drop_by_group_capacity: true
            peak_capacity_microbatchsize: ${device_train_microbatch_size}
            ...
        ```

1. Подбираем сетку batch size;
    - в этом пункте мы перебираем ep size (для разных моделей это могут быть как ep=4,8; так и ep=16,32,64)
    - также микробатч и пр

2. Запустим сетку экспериментов с динамическим роутером DynamicGate. Первые n шагов распределение токенов будет происходить с помощью FirstExpertGroupGate, это позволяет достигнуть лимита в выставленного капасити. Таким образом если не возникает ООМ мы можем быть уверены, что выставленный капасити входит в девайс по памяти. Далее происходит автоматическое переключение на UniformGate, на нём мы можем оценить перф для каждого эксперимента из сетки.
    - Seq Len warmup ДОЛЖЕН БЫТЬ ОТКЛЮЧЕН!
    - мы можем потенциально запускаться не на целом количестве карт, но не забудьте выставить
    - По лучшему перфу мы уже можем примерно прикинуть время обучения (с некоторой погрешностью)
    - мы можем использовать данное нам время обучения и скорость для понимания количества токенов в секунду


3. Теперь мы готовы запустить продовый ран
    - seq len warmup (с 256 до 4к)
    - НЕ указан гейт (дамми или юниформ)
    - включены ВСЕ МоЕ мониторинги
    - БЕЗ гибрида


#### Ручной алгоритм подбора (если хочется немного страданий)

0. Подбираем сетку batch size (на опыте), считаем по [табличке](https://docs.google.com/spreadsheets/d/13lHsOvag-sNvDBcXqMS44OtCcxMO7gxL6ZCNAMxEtDY/edit?gid=0#gid=0) "average tokens with uniform balance", умножаем ее на 2 и ставим как переменную капасити (для каждого батча будет свое значение капасити).
    - в этом пункте мы перебираем ep size (для разных моделей это могут быть как ep=4,8; так и ep=16,32,64)
    - также микробатч и пр

1. Далее, нам нужно проверить, что выбранные капасити не роняют наше обучение по OOM. Для этого запускаем обучение с роутером first group k. Этот роутер напраляет все токены на первых K экспертов, таким образом мы МАКСИМАЛЬНО нагружением первые ранги с экспертами;
    - Seq Len warmup ДОЛЖЕН БЫТЬ ОТКЛЮЧЕН!
    - мы можем потенциально запускаться не на целом количестве карт, но не забудьте выставить

2. Теперь мы уверены, что наш батч влазит и не убивает обучение, мы можем приступить к замеру перфа. Для этого выбираем dummy uniform роутер
    - по лучшему перфу мы уже можем примерно прикинуть время обучения (с некоторой погрешностью)
    - мы можем использовать данное нам время обучения и скорость для понимания количества токенов в секунду

3. Теперь мы готовы запустить продовый ран
    - seq len warmup (с 256 до 4к)
    - НЕ указан гейт (дамми или юниформ)
    - включены ВСЕ МоЕ мониторинги
    - БЕЗ гибрида
