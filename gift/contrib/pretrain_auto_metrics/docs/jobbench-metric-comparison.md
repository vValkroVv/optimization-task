## Результаты

| Замеряемая модель | Результат интеграции | Опубликованный ориентир | Разница, п.п. | Harness интеграции | Судья интеграции |
|---|---:|---:|---:|---|---|
| Qwen3.6-35B-A3B-FP8 | **17,39%**, наш O5 | [18,31% — DataWorld, табл. 3](https://arxiv.org/html/2610.21656v1#S4.T3) | −0,92 | mini-SWE-agent | Qwen3.5-397B-A17B-FP8 |
| Qwen3.8-27B | **28,84%**, наш O5 | [33,4% — таблица Qwen](https://huggingface.co/Qwen/Qwen3.8-Flash-Next#benchmark-results) | −4,56 | mini-SWE-agent | Qwen3.5-397B-A17B-FP8 |
| DeepSeek-V4-Flash-0731 | **37,93%**, клауд Максима | [41,3% — таблица Qwen](https://huggingface.co/Qwen/Qwen3.8-Flash-Next#benchmark-results) | −3,37 | OpenCode 1.14.18 | Qwen3.5-397B-A17B-FP8 |

Точные значения интеграции: `0.1738723076923077`, `0.28837846153846153`
и `0.37925846153846154`. PAM хранит доли 0–1; здесь они умножены на 100.
Во всех трёх случаях — `main`, 65 задач, агрегация `harbor_mean`:
взвешенные оценки рубрик внутри задачи и равный вес каждой задачи в общем среднем.
Задача без числового reward даёт нулевой вклад; знаменатель остаётся 65.

В переписке ориентир Qwen3.8 округляли до «около 30%»; сохранённая таблица
содержит именно **33,4%**. Это приблизительная сверка при отличающихся условиях,
а не доказательство полного воспроизведения опубликованного протокола.

## Условия выбранных прогонов

Параметры шутера взяты из сохранённых `metrics.json.identity` и конфигов;
параметры сервера ниже отмечены отдельно. Лимит ответа не равен окну контекста.

| Параметр | Наш Qwen3.6 | Наш Qwen3.8 | DeepSeek Максима |
|---|---|---|---|
| Harness | mini-SWE-agent; отдельная версия пакета не восстановлена | mini-SWE-agent; отдельная версия пакета не восстановлена | OpenCode 1.14.18 |
| Параллелизм генерации / судейства | `4 / 2` | `4 / 2` | `16 / 16` |
| Лимит времени агента на задачу | 7200 с | 7200 с | 7200 с |
| HTTP timeout модели | 6400 с | 6400 с | 21600 с |
| `max_tokens` агента, на запрос | 131072 | 131072 | 131072 |
| `max_input_tokens` адаптера | 98304 | 98304 | `null`; в отчёте OpenCode указан input limit 131072 |
| Окно контекста inference server | Не восстановлено в этой сводке | 262144 в конфиге и сохранённой команде запуска SGLang | Полный effective config двух серверов не восстановлен |
| Судья | Qwen3.5-397B-A17B-FP8 | Qwen3.5-397B-A17B-FP8 | Qwen3.5-397B-A17B-FP8 |
| Температура судьи | `0.0`, запрос upstream judge | `0.0`, запрос upstream judge | `0.0`, запрос upstream judge |
| `judge_max_tokens` шутера | 65536 | 65536 | 16384; отчёт дополнительно фиксирует OBM reasoning budget 32768, суммарный лимит 49152 |
| HTTP timeout судьи | 21600 с | 21600 с | 21600 с |
| Лимит verifier на задачу | 21600 с | 21600 с | 3600 с |
| Попытки судьи на рубрику | До 3 | До 3 | До 3 |

`max_input_tokens=98304` — значение конфигурации, а не доказанный размер
фактически отправленного prompt: mini-SWE в этой интеграции не обеспечивает
такой входной лимит. Восстановленные параметры не следует принимать за готовый
конфиг повторения с гарантированно тем же effective context.

Для Qwen3.8 конфиг OBM и лог запуска фиксируют `temperature=1.0`, `top_p=0.95`,
`top_k=20`, `enable_thinking=true`, `preserve_thinking=true`,
`reasoning_effort=xhigh`. Сервер модели: TP=4, DP=2; сервер судьи в запросе DAG:
TP=8, DP=1, context=262144, multimodal включён. Это настройки запуска;
эффективные sampling-параметры каждого запроса отдельно не сверялись.
Sampling и reasoning сервера Qwen3.6 в этой сводке не восстановлены.
Эффективный режим reasoning судьи, точные digest использованных образов и
ревизии весов моделей для этих исторических прогонов здесь не установлены.

У Максима DeepSeek использовал два последовательных инференса: сохранены
25 генераций с `thinking=true, reasoning_effort=max`, затем получены ещё
40 с `thinking=true` без явного переопределения effort. Объединение было
согласовано при продолжении запуска. Это смешанный профиль; нельзя описывать
весь результат как единый прогон с `reasoning_effort=max`.

### Полнота и ошибки исторических результатов

| Замер | `complete` | Неразрешённые инфраструктурные ошибки | Числовые rewards | Без числового reward |
|---|---|---:|---:|---:|
| Наш Qwen3.6 | `true` | 0 | 56/65 | 9 |
| Наш Qwen3.8 | `true` | 0 | 61/65 | 4 |
| DeepSeek Максима | `true` | 0 | 64/65 | 1 |

В этих исторических версиях `complete=true` не означает наличие числового
reward для каждой задачи: перечисленные пропуски вошли в среднее нулями.
У DeepSeek генерация содержала два `AgentTimeoutError`, а судейство — один
`RuntimeError` без reward. Разбор сохранённых логов связывает оба таймаута
OpenCode с ожиданием разрешения `external_directory /tmp/*`.
Эти показатели описывают фактически опубликованный тогда результат;
их нельзя использовать как проверку нынешней политики обработки ошибок.

В DataWorld для Qwen3.6 дополнительно указаны средние 38,7 раунда и 60,4 тысячи
response tokens; это наблюдения, а не лимиты. Gemini, названный судьёй других

условия JobBench. Общие настройки сайта JobBench (OpenCode, Grok) и рекомендации
карточки DeepSeek также нельзя приписывать этим двум строкам без подтверждения.

## Артефакты и воспроизводимость

Компактные извлечения метрик, конфигураций, источники и SHA256 исходных файлов:
[`jobbench-metric-comparison.json`](jobbench-metric-comparison.json).
Пути архива в нём относительны к локальному `jobbench_cluster_archive/`;
полные логи, outputs и кэши остаются в этом архиве и не включаются в Git.
Совпадающий SHA256 manifest данных
`1b048bdf0f5142dcc60b2b56befa9729cf00e7d85442ad6316fbb06b45e5a748`
подтверждён для трёх замеров; это проверка manifest, а не повторное хеширование
всех данных или доказательство совпадения с опубликованными датасетами.

Наш Qwen3.6 связан с
[DAG `jobbench-qwen36-qwen397-vision-20f9b728-r4`](https://airflow-dev-pretrain.eye.salute.ru/dags/pam_cluster/runs/jobbench-qwen36-qwen397-vision-20f9b728-r4).
Qwen3.8 — серия `jobbench-qwen38-qwen397-20f9b728-20261019-r*` с продолжением
из кэша. Скоринг Максима —
`jobbench_dsflash0731_qwen35_397b_scoring_c16_20261020T145354Z`;
версия кода подтверждена сохранёнными fingerprints исходников.

Наиболее близкая сверка здесь — Qwen3.6: разница 0,92 п.п. и известный общий
тип harness. Для остальных двух моделей разницы составляют 4,56 и 3,37 п.п.,
но публичные источники не раскрывают протокол достаточно для строгого
парного сравнения. Эти результаты подтверждают работоспособность интеграции
на выбранных профилях; точное совпадение методологии и отсутствие влияния
замены судьи ими не доказаны.
