Подготовленные кандидаты и идеи по трассам

Исходная подборка кандидатов

ID и идеяМеханизм и применимостьСтатус
Kindulov
K1 Softcap + CE Fusion softcap/CE и раннее освобождение chunks. В crop softcap нет; compiled CE уже использует BF16 logits/gradients и FP32 row stats. Полный donor-путь не измерялся. В основной серии есть отдельная stable cap-zero CE адаптация без softcap.
K2 Локальный FFN recompute Сокращает хранение активаций ценой повторных GEMM и SwiGLU; SAC может дублировать работу. Routed donor отвергает FP8. Не измерялся отдельно.
Evko
E1 Hidden z-loss Fusion SwiGLU, FP8 quantization и gate/up z-gradient. Активный z-loss стоит на norm input; BF16 backward inputs увеличивают хранение. Меняет функцию потерь; исходники ядер CudaCherry недоступны.
Runtime-подборка MR41
R1 CompactCEСчитает head и loss для supervised-позиций.Реализация отвергает MTP1.
R2 Streaming prefetchОчередь CPU-батчей глубины 32 перекрывает подготовку данных и обучение.Включён с глубиной 32; измерен вместе с M2, M3 и stable CE.
R3 GFSDP buffers/prefetchВ crop уже включён GFSDP2; нужна конкретизация недостающего механизма и его совместимости с backward/SAC.Отдельного измерения нет.
R4 Frozen BF16 storageХранение замороженных весов в BF16 экономит память.В полном предобучении crop замороженных параметров нет.
R5 Metric accountingРазделяет физические input tokens и supervised tokens.Отдельного прироста скорости не измеряли.

Идеи по анализу трасс

IDМеханизмСтатус
M1Объединить подготовку позиций, масок, auxiliary scaling и MTP targets в одно GPU-ядро.Измерен отдельно; устойчивого TPS-выигрыша нет, в выбранную конфигурацию не входит.
M2Переиспользовать BF16-веса экспертов между микробатчами: одно преобразование на шаг оптимизатора при expert FSDP1.Реализовано и включено в выбранную конфигурацию.
M3Одно ядро для карты и вероятностей маршрутизации вместо цепочки eager-операций.Реализовано и включено в выбранную конфигурацию.
M4Раньше запускать reduce-scatter градиентов FFN, пока продолжается backward блока MTP или слоя 0.Реализовано и измерено.
M5Суммировать счётчики токенов экспертов по группам назначения перед EP all-reduce.Реализовано; компонентный тест и обучение без ускорения. Диагностика не завершена.
M6Сохранять точную keep mask и результат проверки capacity для повторного использования при SAC.Предложение, не измерено.
M7Отправлять ID токенов, значения и градиенты строк владельцам embedding вместо обмена полной таблицей.Реализовано и измерено.
M8Пропуск повторной сборки весов embedding перед backward.Отдельная идея; с compile и SAC не измерялась.

Почему часть улучшений ограничена

ИдеяОценка эффектаОграничение
Norm/residual fusionОценка 0,4–0,5% времени окна из трёх микробатчей для forward + backward; 0,2–0,3% для forward.Расчёт по исторической трассе; peak memory отдельно не оценён.
M5: capacity group countersПолная операция: 91,696→92,816 мкс; сам all-reduce: 78,960→78,976 мкс. Медианы максимума по 8 рангам.Буфер сократился с 1 024 до 64 байт, но коллективы и ожидания остались.
GPU metadata / CUDA GraphsВ старом V2-префиксе GPU idle составлял 3,32%; host wait capacity checks 652,941 мс, GPU idle overlap 6,319 мс.Большая часть ожидания перекрывалась вычислениями; оценка относится к другому workload.
FP8 weight cacheОценка dense quantization: около 0,7% префикса.Нужны память для кэша и контроль его жизненного цикла.
MLA backendТекущий путь использует cuDNN flash.Быстрая совместимая training-замена не установлена.
GDN / local FFN recomputeМеньше сохранённых активаций ценой пересчёта.Локальная политика может дублировать действующий SAC.
GFSDP overlap / MoE metadataТребуют сохранения зависимостей и ожиданий коллективов.BF16 reuse измерен для expert FSDP1; целевой expert FSDP4 требует отдельной проверки.
MoE dispatch/GEMM/combine pipelineПотенциал скорости и peak memory не измерен.Для интеграции нужна отдельная работа по последовательности операций.
