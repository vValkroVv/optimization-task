## Runtime-cost review

The installed public API (`torch/compiler/__init__.py:504-529`) imports Trees and calls `mark_step_begin`; installed Trees `:344-348` decrements one Python integer. Its explicit counter replaces automatic generation tracking (`:2810-2835`), which supports the intended same-generation scope over all four microbatches. Both installed source hashes match the earlier lifetime design's inspected implementation where applicable; this is source evidence, not a measured GPU result.

Added steady host work is one existing observer dispatch and one public Python API/counter call per complete update, independent of token count and accumulation count. First invocation can include lazy module-import cost and must stay outside the stable performance window. Timing observer already requires the shared ObserverState snapshot at `batch_start`; the new callback reuses that snapshot (`base.py:650-657`). A marker-only configuration additionally creates the normal small host snapshot, including tuples of model/optimizer references (`base.py:273-315`), once per update and at fit-start. Snapshot construction reads host step/accumulation values and tensor references; it does not copy tensor data or extract device values.

The callback adds no explicit tensor computation, GPU kernel, device-value read, transfer, synchronization or collective. Precision, masks, routing, FSDP/EP ordering, clipping and optimizer arithmetic are unchanged in source. However, **changing generation ownership changes the compiler's downstream graph-pool lifetime and capture/replay behavior**. More graph-pool retention, recording/recapture or replay differences may materially change memory and integrated runtime. CPU tests and this cost inspection do not bound those effects. Full-target capture/replay, memory and paired performance evidence remain required.
