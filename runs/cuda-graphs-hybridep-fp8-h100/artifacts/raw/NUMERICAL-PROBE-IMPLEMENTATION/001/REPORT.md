# Direct numerical reference recorder

Status: R1/R2/R3 review corrections are implemented in staging. This remains an opt-in diagnostic patch, not production readiness or A/A acceptance. The corrected patch is for targeted reviewer verification; no actual `gift/` paths were written. The Source008 snapshot records base commit `446431dfa191ef0300f116257ae918bc85e38c06`; the README base hash is recorded below.

## Changes

- Added a narrow schema and trainer binding for `create_s0` and `observe`. Observation accepts `updates: 1` (default) or `updates: 10`; it starts at absolute step 2 and stops at `1 + updates`. The dynamic schema importer discovers the added schema module, so no registry edit is needed.
- Added a copy-only pending RNG snapshot accessor. The probe records the RNG serialization bytes emitted by the native save path and verifies the actual restored state; it does not re-sample RNG for later comparison.
- Records actual accumulated preclip gradients, actual postclip gradients, post-update parameters, AdamW `exp_avg`, `exp_avg_sq`, and step tensors, along with the target loss/input/router/state inventory. Each payload is copied to CPU, hashed, written, then checked by a lossless CPU readback. There is no decoder or reconstructed optimizer arithmetic.
- Keeps native clipping, fused AdamW, scheduler, model defaults, checkpoint path and continuation behavior in control. Unsupported optimizer groups, state layouts, or prepared inputs fail the opt-in probe. BlockMask handling follows the pinned fields; callable identity/closure observations are metadata only. The reconstructed auxiliary scale is a scalar in microbatch JSON metadata, not an added tensor-pack family.
- Preserves the complete Source008 README, including its phase-memory append, and adds the probe section in [staged README](staged/gift/torchtitan/experiments/cuda_graph_campaign/README.md). The staged Python and CPU behavior test are under [staged/gift](staged/gift).

## Storage and runtime cost

The agreed live-file cap is 700 GiB with 32 GiB free space reserved. Nominal payload estimates are about 608.408 GiB for ten updates across the five full tensor families and about 36.505 GiB for the native S0 inventory, or 644.912 GiB combined before inputs, partial files, metadata, checkpoints, logs, and other overhead. The writer counts live files against the cap and leaves failed partials for diagnosis.

When enabled, five complete tensor families are persisted per update, about 60.84 GiB globally. The three unchanged preclip hashes of P/m/v add D2H traffic, for about `8F` or 97.35 GiB of large-family D2H per update before input, buffer, scalar, and state reads. Ten updates write about 608.4 GiB and move about 973.5 GiB in these large-family copies. The scalar auxiliary-scale check runs once per microbatch after native weighing. The recorder also performs synchronous writes/fsyncs, CPU readback, and device drains at capture boundaries. It makes no H2D transfer or optimizer arithmetic. With the callback absent, the numerical path installs no hooks and performs no numerical tensor copies or device synchronization. There is no throughput claim.

## Consolidated review corrections

- **R1:** The inventory labels only declared direct `aux_loss_scale` fields as reconstructed by native `AuxLossTracker.weigh`. S0 load compares their identity/layout while requiring every other buffer and direct tensor value to match. Observe wraps native `weigh`, verifies declared modules share the tracker's scale, and records its actual per-part scalar in microbatch JSON after weighing and before forward. It adds no auxiliary-scale tensor-pack family. The CPU regression uses real native `AuxLossTracker`, `declare_aux_loss`, `state_dict`, and `load_state_dict`; it reproduces S0 1/32 versus restored 1, verifies the scale after native weighing, and confirms an unrelated direct tensor mismatch still fails.
- **R2:** Failure JSON is best effort when a payload budget exists; without an initialized budget the probe skips unaccounted diagnostic writes and still reaches collective failure publication. The original error remains in the collective status; active tensor writers are aborted and hooks are closed on failed S0, load, batch, or capture boundaries. Checkpoint, load, step-end, and mid-step capture errors reach collective phase publication even when the diagnostic write fails. CPU fault injection covers secondary filesystem and budget failures. The original review reproductions demonstrating the pre-fix failures remain intact under `../../NUMERICAL-PROBE-REVIEW/001/`.
- **R3:** Post-update P/m/v hashes now reuse the hash returned by the tensor writer. Tests assert the endpoint metadata hash equals the payload entry hash. The documented per-update cost is corrected to about `8F` large-family D2H: five persisted families plus three preclip inventory hashes.
- **Naming:** The callback schema now describes a direct reference probe, not an encoding probe.
- **Resolved checks:** The final staged test command passed **14 tests, 1 warning**. A first run of the new R1 test failed because its fixture used an absolute `output_dir`, which the schema correctly rejects; the fixture was corrected to the required relative path. An intermediate Ruff run caught an undefined helper name in the after-load report path; it was corrected before the final full Ruff pass. The final check details follow.
