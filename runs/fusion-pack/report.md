# Memory-neutral backward optimizations on Hopper

The control uses the production eight-layer crop on eight H100s with S, GPU capacity selection, the five Hopper fusions, all three expert GFSDP switches and folded CE. The folded head sees two sequence chunks, two loss heads and the production vocabulary of 128256. The native campaign retains EP8/eFSDP1, dense FSDP8, B2/S4096, accumulation 32, MTP weight 0.3, model and loss compilation, selective activation checkpointing, EMA, tokenizer, data-002 and the D compiler cache. Each measured window covers updates 11–20, with 20,971,520 global physical input tokens. TPS is total tokens divided by elapsed window time. Memory is the highest PyTorch allocator peak across the eight ranks in that window.

The three-fix package saved 382 MiB allocated and 240 MiB reserved. The independent head change saved 1,003 MiB allocated and 1,000 MiB reserved. Both variants met the two peak-memory gates. All ranks reported the expected folded-CE selection and executed each requested candidate. The source fingerprint, normalized resolved configuration and token counts matched across arms. All eight ranks recorded zero OOMs and zero allocator retries in each window, with stable compilation. The two measured gains apply to separate comparisons against the same control. An all-four combination has no full-training measurement. The owner subsequently selected all four for the canonical production launcher. Across all 20 native updates, the maximum absolute differences from control in TensorBoard total loss and global gradient norm were 0.0002861 and 0.02344 for the package, and 0.0003195 and 0.00838 for staged head dW. A previous folded-CE control with the same normalized config at a different source revision differed from this control by up to 0.0002775 and 0.02734. ## Component evidence

All times use the production shapes. Device event spans and host-inclusive times are kept separate from summed trace kernel durations. Component comparisons run before timing the complete recipe.

- **Hidden z-loss.** A BF16 load with FP32 magnitude, maximum and shifted exponentials feeds the original ATen FP32 sum and final row arithmetic. Backward computes the elementwise derivative and writes BF16 once. All native row statistics, scalar loss and hidden gradients matched bitwise. Eager forward plus backward took 1.160 and 1.161 ms across two controls versus 0.299 and 0.298 ms for two candidates. Peak allocated and reserved both fell by about 512 MiB. [Donors, scope, numerical cases and traces](zloss-component.md)
- **Hidden gradient assembly.** The existing FP32 destination receives disjoint BF16 slices and is cast back to BF16. A fully written BF16 destination removes initialization and both conversions. Ordinary DTensor accumulation retains its existing placement and reduction path. The native folded-head replay supplied both actual gradient chunks. All 67,108,864 gradient elements matched bitwise. Median CUDA-event span was 0.665 ms with FP32 storage and 0.193 ms with BF16 storage. Median wall time was 0.688 and 0.219 ms. Over three calls the trace shows 18 versus six GPU operations and 1.957 versus 0.514 ms of device work. Peak allocated fell by 256 MiB with identical reserved peaks. [Measurements](dhidden-component.json) · [Replay](dhidden_component.py)
- **Head weight gradient.** The isolated replay starts from native hidden states, weights, labels, positions and the update denominator. It captures the two inputs to each actual eager LM-head weight-gradient GEMM. cuBLAS can describe a padded leading dimension, so the experimental writer places each BF16 GEMM result in half of each row of the existing FP32 gradient buffer. The merge loads both halves before overwriting the row. Both BF16 chunk results and the final FP32 gradient matched bitwise over 525,336,576 elements each. Initial event medians were 25.216 and 25.499 ms for identical controls and 23.332 ms for the candidate. Peak allocated and reserved each fell by 1,002 MiB. [Replay](head_dw_component.py) · [cuBLAS matrix layout](https://docs.nvidia.com/cuda/cublas/index.html#cublasltmatrixlayoutattribute-t)
- **GDN scan backward.** On the native rank-zero B2/S4096 fixture, direct stateless `external_gate` backward removed one output scan. The output and all seven gradients matched bitwise in eager execution and under `torch.compile(fullgraph=True)` with production selective checkpointing. All 26 focused backend tests passed. Median CUDA Graph replay fell from 1.148 to 0.976 ms for backward only and from 1.360 to 1.220 ms for the compiled SAC scope. Peak allocated and reserved memory each fell by 64 MiB. [Component results and scope](scan-results.md)
- **Native staged head integration.** On one rank, the folded-CE replay matched the loss, dHidden and accumulated sharded FP32 dW bitwise across two microbatches. It exercised both staged writes, safe reuse of the buffer on an asynchronous stream, the native no-sync and parameter-hook paths, and release and retry after an interrupted forward. The receipt on SR008 is `runs/fusion-pack/artifacts/raw/head-dw-integration-002/rank0.json`, SHA-256 `7f1a3fc75c964b09d9238cc6b6eace0afb60dbefb1bc40d3f4aa3ec42f2db539`. ## Profile budget and candidate selection

At the measured baseline cadence of 11.773 s per update, a 0.2–0.3% throughput gain requires 23.5–35.2 ms less elapsed time. With 32 microbatches per update, this corresponds to 2.20–3.30 ms in a three-microbatch trace if the saving scales and reaches the critical path.

The external-gate backward materialized a 64 MiB attention output solely while reconstructing operands for its VJP. Removing that output is independent of the GDN output normalization and requires no saved forward activation. At six GDN calls per microbatch the measured 0.140 ms reduction per compiled SAC component call corresponds to about 27 ms per update. Hidden z-loss saved roughly 0.86 ms per eager call (about 28 ms across 32 microbatches). Direct two-chunk dHidden assembly saved 0.47 ms per call (about 15 ms per update). These extrapolations motivate the package. The native comparison measures their combined effect. [GDN traces](scan-results.md) · [Hidden z-loss](zloss-component.md) · [dHidden](dhidden-component.json)

The folded-CE traces also show 14 expert-shard FP32 additions on stream 24 over the first three microbatches of update 21. Their summed kernel durations were 17.359 and 17.304 ms on ranks 0 and 1. Of those durations, 16.166 and 16.108 ms overlapped compute on other streams. The trace leaves roughly 1.19 ms per rank outside concurrent compute. Extending the expert GEMM writer to accumulate into persistent gradient storage requires a separate buffer-lifetime and collective analysis. The intersection uses GPU kernels correlated by external ID to `aten::add_` in the innermost `GFSDP::post_backward_reduce (layers.N[efsdp])` scope, and the union of off-stream kernel intervals excluding NCCL and HybridEP.
